What is actually running

    
The force field, the topology parse, every force term and the integrator
    are validated against OpenMM — per-atom forces agree to 5.2×10⁻⁸. Those
    numbers and the commands that produce them are in
    docs/STATUS.md.

    
The GPU force path is complete: bonded, cell list,
    neighbour list, direct-space nonbonded and PME all run on your GPU and
    reproduce OpenMM's total energy to 1.4×10−6 and its
    per-atom forces to 8.8×10−5. The button above runs the
    composed force path and the integrator against the host reference on your own
    hardware; npm run test:gpu runs all fifteen.

    
Minimisation, dynamics, the constraint solver and the barostat all run on
    the device, and a block of steps is encoded into one command buffer, so there
    is no per-step round trip. In NPT, which is the default, the barostat is the
    exception: a Metropolis test is a decision about a number, so the trial
    energy comes back once per volume move — every 25 steps by default, at a
    measured 0.167 ms per step. Measured on a 1190-atom test system:
    1.30 ms per step, about 133 ns/day on the shipped
    defaults — NPT at 2 fs — with an energy drift of 0.48 kJ/mol per ns
    per atom over 20 ps. Throughput falls with system size:
    the same solute in a 12 Å water box is 2854 atoms and 74 ns/day, so
    an alanine dipeptide built with the notebooks' padding is tens of ns/day
    rather than hundreds. A 4 fs timestep roughly doubles it;
    docs/STATUS.md has the decomposition and says what each option
    costs.

    
The structure is drawn by Mol*, RCSB's
    own renderer, vendored under its MIT licence so the page needs no network and
    sends no request when you open it. It costs 1.47 MB gzipped against
    149 KB for the 3Dmol build it replaced, and against 159 KB for all
    of the rest of this program — a deliberate trade for the quality of the
    drawing. Secondary structure is Mol*'s own assignment from the coordinates;
    a chain too short to trace is drawn as ball-and-stick instead, which is why
    a capped tripeptide has no ribbon. The structure appears as loaded, after
    minimisation and at the end of each stage, or every frame if you set
    While running to animate — off by default because drawing every
    report was measured at 17% of a run.

    
Frames are wrapped into the box as they are written,
    whole molecules at a time and on their centroids, which is what OpenMM's own
    DCDReporter does. The running state is never wrapped: the bonded
    forces are not periodic, so a molecule has to stay whole in the integrator's
    array. An earlier version of this page wrote unwrapped frames, which looks
    exactly like the solvent flying away from the solute.

    
Leave Pressure blank for NVT, or give it a value for NPT. The
    barostat is isotropic and synchronises with the browser once per move, which
    costs about 0.3 ms per step.

    
The live analysis follows
    JIGGLE's design, including
    its four-way RMSD split for two-body systems. The one that matters is
    binder fitted on receptor: a whole-complex RMSD averages a
    ligand's drift across every receptor atom that did not move, so a ligand
    coming loose barely registers. Measured here — a binder displaced by
    exactly 0.500 nm shows 0.243 nm in the combined
    trace and 0.500 nm when fitted on the receptor. The
    centroid interface distance misses it too: a 60° rotation of the binder
    about its own centroid moves it by 0.016 nm while the fitted RMSD sees
    0.349 nm.

    
Every metric agrees with MDAnalysis to 2×10−8 nm
    on a trajectory this engine wrote, per-residue RMSF included.

    
What this page does not do: no anisotropic barostat for
    membranes, no binding free energy, no implicit solvent, and no replica
    exchange. The trajectory it writes is a standard DCD so cpptraj, MDAnalysis,
    VMD and MM/GBSA tooling can do the rest.
